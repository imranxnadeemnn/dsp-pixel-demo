# RZR Conversion Pixel — Advertiser Integration Guide

Welcome. This guide shows your web team how to install the **RZR conversion pixel** so RZR can measure the registrations, purchases, and other actions that result from your campaigns. Integration is a single JavaScript tag per page type and typically takes under 30 minutes.

If anything here is unclear, contact your RZR account manager.

---

## 1. What you'll need from RZR

Before you start, RZR will provide:

- **Your pixel URL** — a single script URL, referred to below as `RZR_PIXEL_URL`. It looks like `https://…/exec?action=pixel`.
- **Your `campaign_id`(s)** — one per campaign RZR runs for you.
- **Your tracking landing URL(s)** — your landing page with RZR's tracking parameters pre-attached (RZR generates these; you don't build them by hand).

You will add the pixel tag to two kinds of pages: your **landing page** (where RZR's traffic arrives) and each **conversion page** you want to measure.

Your tracking landing URL will carry several query parameters (e.g. `click_id`, `campaign_id`, `pub_id`, `device_id`) that RZR's systems fill automatically. You don't need to read, build, or preserve these yourself beyond the one rule in section 6 — just make sure they survive any redirect on your landing flow.

## 2. How it works (in brief)

When RZR sends a visitor to your landing page, the URL carries a unique click identifier. The pixel reads it and stores it in a first-party cookie on your domain. Later, when that visitor completes an action (registers, purchases, etc.) on your site, the pixel reads the cookie and tells RZR which click led to the conversion. No personal data is stored in the cookie — only campaign and click identifiers.

**Important:** the pixel must be on your **landing page** (to capture the click) and on each **conversion page** (to record the action), and these pages must be on the **same domain**.

## 3. Install the pixel

In most cases your RZR contact will send you ready-made tags (generated for your account, including a `data-netw` network attribute) — just paste each one on the matching page and keep all `data-*` attributes intact. The templates below show what those tags look like; replace `RZR_PIXEL_URL` with the URL RZR gave you. Add the appropriate tag just before the closing `</body>` tag on each page.

### 3.1 Landing page (required)

This captures the click and drops the attribution cookie. Place it on the page your RZR campaign links to. Your real tag from RZR includes a `data-netw` (network ID) attribute — keep it:

```html
<script src="RZR_PIXEL_URL" data-event="landing" data-netw="RZR-NW-001"></script>
```

No other setup is needed here — the pixel reads the tracking parameters from the page URL automatically.

### 3.2 Registration / sign-up page

Place this on the page shown after a user successfully registers or submits a lead form.

```html
<script src="RZR_PIXEL_URL" data-event="registration"></script>
```

### 3.3 Purchase / order confirmation page

Place this on your order-confirmation ("thank you") page. Include the order value, currency, and a unique order ID.

```html
<script src="RZR_PIXEL_URL"
        data-event="purchase"
        data-value="49.99"
        data-currency="USD"
        data-order-id="ORDER-10231"
        data-txn-id="ORDER-10231"></script>
```

`data-txn-id` should be your unique order/transaction number. RZR uses it to avoid double-counting if the confirmation page is reloaded.

### 3.4 Custom event (any other action)

For actions like add-to-cart, app install, or subscription start, use `custom` and give it a name.

```html
<script src="RZR_PIXEL_URL"
        data-event="custom"
        data-event-name="add_to_cart"
        data-value="19.00"
        data-currency="USD"></script>
```

### 3.5 Dynamic values (when the amount is only known at runtime)

If the purchase value or order ID is generated by your app at runtime (e.g. a cart total), load the pixel in manual mode and call `rzrTrack()` once you have the data:

```html
<script>window._dsp = { event: "manual" };</script>   <!-- prevents auto-firing -->
<script src="RZR_PIXEL_URL"></script>
<script>
  // call this after the order is confirmed and the total is known:
  rzrTrack("purchase", {
    value:   String(orderTotal),   // e.g. "49.99"
    currency:"USD",
    orderId: orderNumber,
    txnId:   orderNumber
  });
</script>
```

`rzrTrack(event, options)` accepts `value`, `currency`, `orderId`, `txnId`, and (for custom events) `eventName`. Values you pass at runtime always take precedence over `data-*` attributes. (`rzrTrack` is also available under the name `dspTrack` — either works.)

## 4. Parameters you control

On conversion pages you may provide the following. All are optional except the event type, but `value`/`currency` enable revenue reporting and `txn_id` enables de-duplication.

| Attribute / option | Example | Purpose |
|---|---|---|
| `data-event` / event | `purchase` | The action type: `landing`, `registration`, `purchase`, or `custom`. |
| `data-event-name` / `eventName` | `add_to_cart` | A label for `custom` events. |
| `data-value` / `value` | `49.99` | Conversion/order value. |
| `data-currency` / `currency` | `USD` | ISO currency code. |
| `data-order-id` / `orderId` | `ORDER-10231` | Your order/lead reference. |
| `data-txn-id` / `txnId` | `ORDER-10231` | Unique ID for de-duplication. |

You do **not** need to handle `click_id`, `campaign_id`, or other RZR identifiers — the pixel manages those automatically via the cookie.

## 5. Test your integration

1. **Open your landing page using the tracking URL RZR gave you** (it includes `?click_id=…`). In your browser's developer tools, under Application ▸ Cookies, confirm a cookie named `_dsp_attr` now exists for your domain.
2. **Complete a test conversion** (register or place a test order) in the same browser. The pixel will send the event to RZR.
3. **Confirm with RZR** that your test landing view and conversion were received, with the correct event type and value. Your RZR contact can see these in near real-time.

A simple way to sanity-check loading: open your page, and in the developer console confirm there are no errors referencing the pixel and that `typeof rzrTrack === "function"`.

## 6. Placement and timing tips

Place the tag where it will reliably load on a successful action — typically the server-rendered confirmation page, not inside a modal that may be skipped. For single-page apps, fire conversions with `rzrTrack()` at the moment the success state is reached rather than relying on a page load. Keep the landing-page tag on the exact page your campaign links to; if your landing flow redirects, ensure the tracking parameters survive the redirect (RZR can help configure this).

## 7. Privacy

The pixel stores only campaign and click identifiers plus a timestamp in a first-party cookie on your domain — no names, emails, or other personal data. If you operate under consent requirements (e.g. GDPR/CCPA), load or fire the pixel only after the user has given the relevant consent, the same way you gate other marketing tags. Talk to your RZR contact about consent-mode options.

## 8. Troubleshooting

If conversions aren't being recorded, check that the **landing-page tag is present and the visitor actually arrived via the RZR tracking URL** (the `_dsp_attr` cookie must exist before the conversion). Confirm the **landing and conversion pages share the same domain**. Make sure the conversion tag's `data-event` is set correctly and, for purchases, that `data-value` and `data-txn-id` are populated. Verify the `RZR_PIXEL_URL` is exactly what RZR provided. If you use an ad/script blocker during testing, disable it for your own site. If problems persist, send your RZR contact the page URL and a screenshot of the cookie and console.

## 9. FAQ

**Will this slow down my site?** No. The pixel is tiny, loads asynchronously, and fails silently if anything goes wrong.

**Do I need a backend or server changes?** No. It's a client-side JavaScript tag only.

**What if a user converts days later?** They're attributed as long as the `_dsp_attr` cookie is still present (default window is up to 30 days; some browsers shorten cookie lifetimes).

**Can I track multiple events on one page?** Yes — use the `rzrTrack()` API to fire additional events, or place multiple tags. Use distinct `txn_id`s where relevant.

**Can I reuse the same tag across pages?** Use the same `RZR_PIXEL_URL`, but set the correct `data-event` for each page type.
